### 3.2 Key Integration Chains
1. **Desktop Launch & Audio Subsystem (Phase 1 → Phase 4 → Phase 5):**
   - Wrapper `~/.local/bin/voicemode` executes under isolated `.venv/` Python 3.12 runtime.
   - `voice.py:Recorder` captures 16 kHz audio via PortAudio over PipeWire.
   - `voice.py:play_cue_async` outputs non-blocking auditory feedback.
   - Diagnostic probes (`voice --doctor`) interrogate WirePlumber volume/mute status and PipeWire properties.
2. **Text Transcription & Wayland Typing (Phase 1 → Phase 2 → Phase 4 → Phase 5):**
   - Faster-Whisper `small.en` int8 CPU inference produces transcripts.
   - `voice.py:insert_text` copies text to clipboard upfront via `wl-copy`.
   - `voice.py:type_text` detects `wtype` on Wayland and injects keystrokes via stdin with settling pauses.
   - Hyprland daemon toggle (`SUPER + SHIFT + M`) initiates and terminates recording via `SIGUSR1`.
3. **Selection Capture & Kokoro TTS Pipeline (Phase 3 → Phase 4 → Phase 5):**
   - `voice.py:selected_or_clipboard_text` reads `wl-paste --primary` with 1.0s timeout.
   - Kokoro ONNX offline synthesis processes text at clamped speed [0.5, 2.0].
   - Headless `ffplay` streams audio tagged with PipeWire application name `voicemode`.
   - Symmetric STT/TTS mutex terminates active recording if TTS is started, and vice versa.
   - Interruption handling instantly kills playback without false error toasts.
4. **Diagnostic & Recovery Tooling (Phase 5 → System):**
   - `voice --doctor` inspects 5 subsystems and outputs contextual `pacman` remediation commands.
   - `voice --kill` detects active workers or stale PID locks and resets daemon state to idle.
   - `voice --verify` executes 3 tiers of tests including synthetic loopback in <4s.

### 3.3 End-to-End User Workflows
- **Flow 1 (Push-to-Talk STT Dictation):** Complete (`SUPER + SHIFT + M` -> start chime -> audio record -> stop chime -> transcribe -> `wtype` injection).
- **Flow 2 (TTS Speak-Selection):** Complete (Highlight text -> `SUPER + T` -> selection read -> normalize -> synthesize -> `ffplay` audio output -> toggle interrupt).
- **Flow 3 (Daemon Recovery):** Complete (`voice --kill` -> process termination -> stale PID unlinking -> idle state).
- **Flow 4 (System Diagnostics & Verification):** Complete (`voice --doctor` & `voice --verify` -> 3 tiers executed -> markdown/JSON reports).
