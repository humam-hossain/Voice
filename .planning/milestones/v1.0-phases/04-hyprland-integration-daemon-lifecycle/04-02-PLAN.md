<Plan 04-02: Hardened Background Daemon Lifecycle, Signals, Mutex & Feedback>
<objective>
Harden the voicemode background daemon process management, PID tracking, and signal handling to deliver an industrial-grade, race-free, focus-safe user experience under Wayland/Hyprland. Implement explicit lifecycle state tracking in `recorder.pid` (`starting` -> `recording` -> `transcribing` -> `idle`), eliminate double-tap startup crashes via 300ms readiness polling, protect active transcription/typing with busy error chime feedback, differentiate `SIGUSR1` (graceful stop & type) from `SIGTERM`/`SIGINT` (clean abort & unlink), enforce symmetric STT/TTS mutual exclusion to eliminate audio bleed, verify process identity against Linux PID recycling via `/proc/<pid>/cmdline`, arm 60s transcription and 300s recording safety watchdogs, and eliminate Wayland focus stealing during `wtype` keystroke simulation by suppressing routine toasts and configuring low-urgency TTS toasts (`-u low -t 2000`).
</objective>

</execution_context>

<threat_model>
## ASVS Level 1 Threat Analysis

- **T-04-02: PID Recycling Misdirection & Arbitrary Signal Injection (ASVS 1.15.1 - Tampering / Denial of Service)**
  - *Description:* On high-turnover Linux systems, process IDs wrap around. If a voicemode daemon terminates abruptly leaving a stale PID file, and another unrelated application (or system service) acquires that same PID, a subsequent `voice --toggle` or `stop_tts` executing blind `os.kill(pid, signal.SIGUSR1)` would send unexpected signals to that unrelated process, potentially causing crashes or data corruption.
  - *Severity:* High
  - *Mitigation:* Hardened `process_alive(pid)` checks `os.kill(pid, 0)` AND inspects `/proc/<pid>/cmdline` to ensure the process command line contains `"voice"`, `"python"`, or `"voicemode"` tokens per D-15. If cmdline does not match, the process is treated as dead and the stale PID file is pruned.
- **T-04-04: Daemon Deadlock & Zombie State during Transcription or Typing (ASVS 11.1.4 - Denial of Service)**
  - *Description:* If Whisper inference deadlocks or `wtype` hangs due to a compositor bug or pipe stall, the background worker remains stuck indefinitely in `transcribing` state. Because the PID file is locked, all subsequent hotkey presses emit busy chimes, permanently locking the user out of speech dictation.
  - *Severity:* High
  - *Mitigation:* Arm an asynchronous 60-second transcription watchdog timer (`threading.Timer(60.0, ...)`) wrapping transcription and typing. If 60s expires, the watchdog unlinks the PID file, logs an error, and terminates the daemon (`os._exit(1)`) per D-16.
- **T-04-06: Double-Tap Startup Race Process Crash (ASVS 11.1.4 - Denial of Service)**
  - *Description:* When `voice --toggle` spawns a child worker (`subprocess.Popen`), Python takes ~150-300ms to boot and register custom signal handlers. If the user rapidly double-taps `SUPER + SHIFT + M` within 100ms, the second invocation reads the child PID and sends `SIGUSR1`. Because the child still has default signal handlers (`SIG_DFL`), Linux immediately kills the process without logging or error output.
  - *Severity:* High
  - *Mitigation:* The parent immediately writes `<pid> starting` to `recorder.pid`. When `toggle_background_recording` detects state is `"starting"`, it polls `read_pid_state()` up to 300ms waiting for the child to write `"recording"` before delivering `SIGUSR1` per D-11.
- **T-04-07: Focus-Stealing Keystroke Disruption & Window Focus Drift (ASVS 1.1.2 - Tampering / Denial of Service)**
  - *Description:* Under Wayland compositors (Hyprland), notification daemons (SwayNC, Mako, Quickshell) display notification popups as Wayland surfaces that momentarily capture compositor input focus. If voicemode displays routine toasts ("Recording...", "Transcribing...", "Transcript inserted.") right before or during `wtype` keystroke simulation, the keystrokes are swallowed by the notification overlay or dropped, corrupting user input.
  - *Severity:* High
  - *Mitigation:* Routine notifications are suppressed during normal STT dictation per D-17. Feedback relies entirely on auditory sine chimes (880 Hz start, stop chime, 5s reminder cue tick). STT toasts are strictly reserved for exceptional states (errors, no speech, max duration ceiling) per D-18. TTS toasts are configured with low urgency and quick auto-dismiss (`-u low -t 2000`) per D-20.
- **T-04-09: Audio Bleed & Concurrent Audio Device Conflict (ASVS 11.1.4 - Denial of Service)**
  - *Description:* If TTS playback is active over the speakers when the user presses `SUPER + SHIFT + M` to start STT dictation, speaker output bleeds into the microphone stream, contaminating the Whisper transcription. Conversely, starting TTS while STT is recording leads to concurrent audio access.
  - *Severity:* Medium
  - *Mitigation:* Symmetric mutual exclusion per D-14: starting STT recording immediately invokes `stop_tts(args, quiet=True)` to silence speaker output; starting TTS invokes `cancel_active_stt()` (sending `SIGTERM` to abort recording cleanly).
</threat_model>
