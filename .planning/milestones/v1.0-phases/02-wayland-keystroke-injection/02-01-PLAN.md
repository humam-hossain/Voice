# Plan 02-01: Wayland Typing Engine & Rootless Shortcut Simulation

## Executive Summary

Plan 02-01 implements the core Wayland keystroke injection engine for `voicemode` on Arch Linux under Hyprland. It replaces reliance on root-privileged `ydotoold` with native, rootless keystroke synthesis via `wtype` over the `zwp_virtual_keyboard_v1` protocol. It introduces transcript normalization (newline-to-space substitution and whitespace trimming), stdin text piping (`wtype -`) to eliminate shell injection hazards and command length limits, mitigation of an upstream `wtype` crash bug when typing delay is 0ms, pre-typing settling pauses (50ms) to ensure modifier key release, and rootless simulated paste shortcuts (`Ctrl+V` and `Ctrl+Shift+V`). It also establishes the automated unit test foundation in `tests/test_wayland_input.py`.

## Artifacts this phase produces

- `/home/pera/github_repo/Voice/tests/test_wayland_input.py` (Automated unit test suite establishing mock subprocess verification for Wayland input)
- `voice.py:normalize_typed_text(text: str, keep_newlines: bool = False) -> str` (Transcript normalization helper)
- `voice.py:resolve_wayland_backend(args: argparse.Namespace) -> Optional[str]` (Backend resolution prioritizing `wtype` over `ydotool`)
- `voice.py:type_text(text: str, args: argparse.Namespace) -> bool` (Rootless Wayland typing engine with stdin piping, delay calibration, and timeout protection)
- `voice.py:paste_clipboard(text: str, args: argparse.Namespace, shortcut: str = "ctrl+v") -> bool` (Rootless simulated paste sequences via `wtype` modifiers with fallback)

## ASVS Level 1 Threat Analysis

- **T-02-01: Command Injection & Metacharacter Exploitation via Transcribed Speech (ASVS 5.3.4)**
  - *Description:* Transcripts containing shell metacharacters (e.g. `;`, `|`, `&`, `$`, `` ` ``, `"`, `'`) could trigger command execution if interpolated into shell strings or CLI argument arrays. Furthermore, transcripts starting with hyphens (e.g. `--help`, `-v`) could be parsed as CLI flags.
  - *Severity:* High
  - *Mitigation:* Text is passed strictly across a POSIX pipe to `wtype` via standard input (`subprocess.run(cmd, input=text, text=True, shell=False)` with argument `-`). Stdin piping isolates the payload completely from argument parsing per D-11.
- **T-02-02: Denial of Service / Process Hang via Stalled Wayland Socket (ASVS 11.1.4)**
  - *Description:* If the Wayland compositor socket stalls or the virtual keyboard manager deadlocks, an unmanaged child process could block the recording daemon indefinitely.
  - *Severity:* Medium
  - *Mitigation:* All child process invocations (`wtype`, `ydotool`, `xdotool`) enforce a strict 15.0s timeout (`timeout=15.0`) per D-09. If a process exceeds this limit, `subprocess.TimeoutExpired` is caught and handled cleanly without crashing the daemon.
- **T-02-03: Accidental Message Dispatch via Internal Newlines (ASVS 5.1.2)**
  - *Description:* `wtype` hardcodes `\n` to `XKB_KEY_Return`. In chat applications (Slack, Discord) or terminal shells, dictating a sentence with internal newlines would press Return and trigger unintended message dispatch or shell execution.
  - *Severity:* Medium
  - *Mitigation:* All internal newlines (`\r\n`, `\r`, `\n`) are replaced with spaces by default via `normalize_typed_text` per D-12 and trimmed per D-14, preventing unintentional Return keystrokes. Users dictating multi-line code can explicitly opt in via `--keep-newlines` per D-13.
</threat_model>
