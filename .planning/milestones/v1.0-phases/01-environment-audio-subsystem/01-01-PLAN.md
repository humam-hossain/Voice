# Plan 01-01: Environment & Dependency Foundation

## Executive Summary

Plan 01-01 establishes the Python 3.12 execution foundation for `voicemode` on Arch Linux. It transitions the workspace to an isolated, deterministic Python 3.12 virtual environment managed by `uv`, installs all STT (`faster-whisper`, `sounddevice`, `numpy`) and TTS (`kokoro-onnx`, `soundfile`, `edge-tts`) dependencies upfront with full extras, and provides a zero-activation desktop launcher script (`~/.local/bin/voicemode` with symlink `~/.local/bin/voice`) pre-configured with PipeWire client labeling.

## Artifacts this phase produces

- `/home/pera/github_repo/Voice/pyproject.toml` (Updated Python 3.12 constraint and packaging metadata)
- `/home/pera/github_repo/Voice/.venv/` (Isolated Python 3.12 virtual environment with all extras installed)
- `/home/pera/.local/bin/voicemode` (Executable desktop launcher script with PipeWire stream properties)
- `/home/pera/.local/bin/voice` (Convenience symlink pointing to `~/.local/bin/voicemode`)

## Reversibility Gate

If any dependency compilation or wheel installation fails:
1. Discard working directory changes: `git checkout pyproject.toml`
2. Remove created virtual environment: `rm -rf /home/pera/github_repo/Voice/.venv`
3. Remove user launcher and symlink: `rm -f ~/.local/bin/voicemode ~/.local/bin/voice`

<threat_model>
## ASVS Level 1 Threat Analysis

- **Threat 1: Untrusted Dependency Resolution / Supply Chain Tampering (ASVS 10.2.1)**
  - *Description:* Malicious packages or mismatched binary wheels could compromise user execution during installation.
  - *Severity:* High
  - *Mitigation:* Explicitly install dependencies defined in `pyproject.toml` using `uv pip install -e ".[kokoro,edge]"` which uses PyPI HTTPS repository index with SHA256 integrity verification. System package manager (`pacman`) is not invoked per D-03.
- **Threat 2: Command Injection via Launcher Wrapper (ASVS 5.3.4)**
  - *Description:* Unquoted arguments passed through `~/.local/bin/voicemode` could allow arbitrary shell execution if evaluated in bash.
  - *Severity:* Medium
  - *Mitigation:* The launcher script strictly executes `exec "$VENV_PYTHON" "$VOICE_SCRIPT" "$@"` with rigorous variable and argument quoting, prohibiting `eval` or unquoted string interpolation.
- **Threat 3: Privilege Escalation via Sudo/Root Execution (ASVS 1.14.1)**
  - *Description:* Executing setup or scripts as root could damage system state or expose unnecessary root privileges.
  - *Severity:* High
  - *Mitigation:* All tasks execute strictly as the unprivileged desktop user (`pera`) in user-space (`~/.local/bin` and repository `.venv`).
</threat_model>

### Task 01-01-02: Desktop Launcher Script & Global Symlink Setup

<read_first>
- `/home/pera/github_repo/Voice/.planning/phases/01-environment-audio-subsystem/01-PATTERNS.md` (§2.1 Desktop Launcher Script)
- `/home/pera/github_repo/Voice/.planning/phases/01-environment-audio-subsystem/01-RESEARCH.md` (§6 Launcher Script & Desktop Invocation Architecture)
</read_first>

<action>
1. Ensure the user's local binary directory exists:
   ```bash
   mkdir -p ~/.local/bin
   ```
2. Create `/home/pera/.local/bin/voicemode` with 0755 permissions per **D-01** and **D-11**:
   ```bash
   cat << 'EOF' > ~/.local/bin/voicemode
   #!/usr/bin/env bash
   # voicemode launcher - Arch Linux / Hyprland
   set -euo pipefail

   REPO_DIR="/home/pera/github_repo/Voice"
   VENV_PYTHON="${REPO_DIR}/.venv/bin/python"
   VOICE_SCRIPT="${REPO_DIR}/voice.py"

   # Enforce PipeWire and PulseAudio client node labeling (D-11)
   export PULSE_PROP_application.name="voicemode"
   export PIPEWIRE_PROPS='{ application.name = voicemode }'

   if [ ! -x "${VENV_PYTHON}" ]; then
       echo "Error: voicemode virtualenv not found at ${VENV_PYTHON}" >&2
       echo "Run Phase 1 setup to initialize the Python 3.12 virtualenv." >&2
       exit 1
   fi

   exec "${VENV_PYTHON}" "${VOICE_SCRIPT}" "$@"
   EOF
   chmod 755 ~/.local/bin/voicemode
   ```
3. Create convenience symlink `/home/pera/.local/bin/voice` pointing to `~/.local/bin/voicemode`:
   ```bash
   ln -sf ~/.local/bin/voicemode ~/.local/bin/voice
   ```
4. Verify execution of both `voicemode` and `voice` from outside the virtual environment.
</action>
