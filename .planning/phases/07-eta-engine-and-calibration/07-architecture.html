3. ETA Formula Breakdown

ETA-01: ETA = remaining_load + rate × remaining_audio + finalize + insert
where rate = Σ(decode_s) / Σ(audio_s) — ratio of sums, never mean of ratios.

Display Rules Summary

RuleBehavior
FormatSingle integer + s suffix. ~ prefix if uncalibrated. E.g. ~12s, 5s
Hidden duringstarting, recording
Shown duringtranscribing, finalizing
Never showsNegative, zero, fractional, or ranged values
DownwardImmediate step to lower integer
Upward≥1.0s jump AND ≥2.0s debounce
Countdown end2s → 1s (hold 1s) → Finishing…
Extended overrunStay on Finishing… until text insertion
~ prefixPersists entire countdown for uncalibrated runs

calibration.json Schema (per key)

FieldTypePurpose
sum_decode_sfloatAccumulated decode time (numerator of rate)
sum_audio_sfloatAccumulated audio duration (denominator of rate)
ratefloatDerived: sum_decode_s / sum_audio_s
finalize_sfloatCalibrated finalize time
load_sfloatCalibrated model load time
nintSample count at this key
residualsfloat[]Last 20-30 prediction errors (for MAD confidence)
confidencefloat1.0 - MAD/median_residual, clamped [0, 1]
updated_atfloatEpoch timestamp of last update
Atomic writes: All writes to calibration.json use tempfile + os.replace with 0o600 permissions — matching the existing atomic_write_json() pattern. Readers never see torn JSON.

Resolved Conflicts

ConflictResolution
Ratio of sums vs median of per-run ratesRatio of sums wins (ETA-01). MAD/median used only on prediction residuals for confidence, not for rate fitting.
eta_source: cold vs prior overlapDistinct. cold = known cold boot with inflated load; prior = no calibration data at all (fresh install). Same prior values, different diagnostic meaning.
Incremental accumulators vs median-based fittingAccumulators for rate, residuals window for confidence only. No per-run rate array needed for the core estimate.
