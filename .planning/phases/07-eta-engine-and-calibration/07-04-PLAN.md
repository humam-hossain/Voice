<objective>
Close UAT Gap G-07-7 by connecting parallel incremental chunk transcription progress and live ETA prediction to the desktop status pill.

Purpose: Provide user visibility into both audio recording duration and parallel chunk transcription progress (`X:XX | X:XX`) during recording, and display the countdown ETA pill (`~Xs` / `Finishing…`) during transcription.
Output:
- `transcribed_audio_s` field in `voicemode_telemetry.py` status schema and validation
- Live parallel transcription publishing in `voice.py` `worker_consumer`
- Quickshell `Voice.qml` service observer for `status.json`
- Quickshell `VoicePill.qml` dual timer (`X:XX | X:XX`) and live ETA display
- Unit tests verifying the status contract extension and live chunk progress
</objective>

<tasks>

<task type="auto" name="1. Extend status schema and worker publishing for transcribed_audio_s">
1. In `voicemode_telemetry.py`:
   - Add `"transcribed_audio_s"` to `STATUS_V1_KEYS`.
   - In `build_status()`, accept `transcribed_audio_s: Optional[float] = None`, ensure non-negative float or None.
   - In `validate_status()`, validate `transcribed_audio_s` if present.
   - Update `print_status` to expose `transcribed_audio_s` in `--status --json` output.

2. In `voice.py`:
   - In `status_state` dict (line ~2183), initialize `"transcribed_audio_s": 0.0`.
   - In `worker_consumer()`:
     - As each audio chunk finishes transcribing and produces a `TranscriptionEvidence` result:
       - Accumulate total decoded audio duration: `transcribed_s = sum(r.audio_s for r in results if r and r.audio_s)`.
       - Publish updated status with `transcribed_audio_s=transcribed_s` and `segments_done=len(results)` even while recording is active (`state="recording", phase="record"`).
   - In `heartbeat_worker()`:
     - Preserve and re-publish current `transcribed_audio_s` during periodic heartbeats.

3. In `tests/test_status_contract.py`:
   - Add unit tests verifying `transcribed_audio_s` schema acceptance, validation, and JSON serialization.
</task>

<task type="auto" name="2. Connect Quickshell Voice.qml to status.json and expose live properties">
1. In `/home/pera/.config/quickshell/ii/services/Voice.qml` (and parent repo `/home/pera/github_repo/.dotfiles/restow/quickshell/.config/quickshell/ii/services/Voice.qml`):
   - Add `readonly property string statusPath: runtimeDir + "/status.json"`.
   - Add a `FileView` for `statusPath` (`id: statusFile`).
   - Add reactive properties:
     - `property real transcribedAudioSeconds: 0.0`
     - `property string formattedTranscribedDuration: "0:00"`
     - `property var etaRemainingSeconds: null`
     - `property string etaSource: ""`
     - `property bool etaOverrun: false`
     - `property string etaPillLabel: ""`
   - In `poll()`:
     - Reload `statusFile`.
     - If `statusFile.text()` contains valid JSON:
       - Parse `const st = JSON.parse(statusFile.text())`.
       - Update `sttState` from `st.state` (if valid, falling back to pid check).
       - Read `st.transcribed_audio_s`:
         - If present and > 0, set `transcribedAudioSeconds = st.transcribed_audio_s` and `formattedTranscribedDuration = formatDuration(Math.floor(st.transcribed_audio_s))`.
       - Read `st.eta_remaining_s`, `st.eta_source`, `st.overrun`:
         - Set `etaRemainingSeconds = st.eta_remaining_s`.
         - Format `etaPillLabel`:
           - If `st.overrun === true`: `"Finishing…"`.
           - Else if `st.eta_remaining_s !== null && st.eta_remaining_s !== undefined`:
             - Prefix `~` if `st.eta_source === "prior"` or `st.eta_source === "cold"`, followed by `st.eta_remaining_s + "s"`.
     - When `sttState === "idle"` and `ttsState === "idle"`:
       - Reset `transcribedAudioSeconds = 0.0`, `formattedTranscribedDuration = "0:00"`, `etaPillLabel = ""`.
</task>

<task type="auto" name="3. Update VoicePill.qml for dual timer (X:XX | X:XX) and ETA countdown">
