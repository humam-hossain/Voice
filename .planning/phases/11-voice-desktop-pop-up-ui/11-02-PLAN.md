# Plan 11-02: VoicePill Wiring, Hover Gating, Parity & End-to-End System Validation

## Executive Summary

This plan connects `VoicePopup.qml` into `VoicePill.qml`, implementing the hover intent trigger and the critical hover-suppression gating during active recording (D-01). It supersedes direct report opening on pill left-click in favor of the dedicated popup report button (D-02). Finally, it synchronizes all live dotfiles components with their repository mirrors, enforces full parity, and executes the complete test suite.

---

## Threat Model (ASVS Level 1)

<threat_model>
- **T-11-01: Accidental Microphone Disruption / Focus Loss on Hover**
  - *Risk:* Inadvertent cursor drift over the bar during active dictation could trigger a popup window that distracts the user or disrupts compositor focus before keystroke injection.
  - *Mitigation:* `VoicePill.qml` conditionally binds `hoverTarget: (Voice.overallState !== "recording" || active) ? pillMouseArea : null`. If closed and recording is active, hoverTarget evaluates to null, blocking all hover events.
- **T-11-02: Broken Dotfiles Synchronization Drift**
  - *Risk:* Divergence between live dotfiles (`~/.dotfiles/restow/...`) and repository references (`integrations/quickshell/...`) leads to untested configurations in production or broken deployments.
  - *Mitigation:* Hermetic regression test `test_voice_popup_and_pill_dotfiles_parity` asserts 100% byte-for-byte equality across both files.
- **T-11-03: Stale State and Memory Leaks in Quickshell Singleton**
  - *Risk:* Long-running background processes or improper event connections in QML could accumulate timers or block garbage collection.
  - *Mitigation:* `StyledPopup` uses `LazyLoader` ensuring popup child items are unloaded when inactive; `FileView` uses passive Qt event monitoring.
</threat_model>
