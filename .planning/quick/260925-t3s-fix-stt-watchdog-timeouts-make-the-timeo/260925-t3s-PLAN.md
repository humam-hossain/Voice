# Quick Plan: Make STT watchdog timeouts configurable and recoverable

**Goal:** Long dictations get enough time for model loading and transcription, and a true watchdog expiry is logged, reported, and leaves the audio file available for recovery.

**Files in scope:** `voice.py`, `tests/test_hyprland_daemon.py`

## Tasks

### Task 1: Configure the STT timeout and report expiry with the retained WAV location
- Add `VOICE_STT_TIMEOUT_SECONDS` with a 300-second default. Accept only a valid positive seconds value; use the default when the environment value is missing or invalid.
- Use the configured duration for the existing watchdog, which covers both Whisper model loading and transcription, and keep cancelling it on normal completion.
- Pass the worker arguments, WAV path, and configured duration to the expiry handler. Have it report a `TimeoutError` through `report_stt_failure()` with a clear timeout stage, elapsed limit, and recovery path, then remove the PID state and terminate the stuck inference process.
- Extend `report_stt_failure()` only as needed to record the complete recovery path in `voice.log` and preserve a usable WAV path and log pointer in the bounded critical notification. Ensure timeout shutdown retains the failed WAV even if the worker cleanup flow changes; preserve the current cleanup and automatic insertion behavior on successful dictation.
- Add focused unit coverage for timeout configuration fallback/validation, watchdog failure reporting and exit handling, and recovery WAV visibility in the bounded critical notification. Update the existing test that calls the watchdog's former signature.
- Run the daemon test module, full unittest suite, and `uv run python -m py_compile voice.py tests/test_hyprland_daemon.py`. Record that unit tests do not reproduce a multi-minute inference timeout or verify desktop notification delivery in a live Wayland session.

**Verify:** Unit tests confirm timeout defaults/overrides, invalid values fall back safely, watchdog expiry reaches the shared reporter and terminates the worker, and the critical notification remains bounded while identifying recovery audio. Source inspection confirms the timer spans model loading and transcription, and normal success still cancels the timer and follows the existing insertion/cleanup path.

**Done:** The watchdog defaults to 300 seconds, supports a valid positive `VOICE_STT_TIMEOUT_SECONDS` override, and reports a stage-specific critical notification and detailed log entry that identify the retained audio file.

## Security Review

Configured review basis: OWASP ASVS Level 1 (opportunistic); blocking threshold: high, per `.planning/config.json`.

Trust boundaries: local process environment into the background STT worker; local audio path and failure details into the user's desktop notification and runtime log.

| Threat ID | STRIDE category | Component | Severity | Disposition | Mitigation or rationale |
|-----------|-----------------|-----------|----------|-------------|-------------------------|
| T-260925-T3S-01 | Denial of Service | STT timeout configuration | low | mitigate | Reject invalid or non-positive timeout values by falling back to 300 seconds, so malformed local configuration cannot trigger immediate expiry or disable the watchdog. |
| T-260925-T3S-02 | Information Disclosure | STT failure notification | low | accept | The absolute recovery path is shown to the same local desktop user who owns the recording; the notification contains no dictated text or audio contents, and the path is needed to recover the failed recording. |

No threat reaches the configured high blocking threshold.
