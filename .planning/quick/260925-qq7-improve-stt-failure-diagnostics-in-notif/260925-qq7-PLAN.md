# Quick Plan: Improve STT failure diagnostics in notifications and logs

**Goal:** When background push-to-talk STT fails, identify the failing stage in the desktop notification and leave enough technical context in `voice.log` to locate and diagnose the underlying model, inference, recording, or insertion failure.

**Files in scope:** `voice.py`

## Tasks

### Task 1: Trace Whisper model-loading failures to a stage-aware notification and log entry
- Add a focused STT failure reporter in `voice.py` and wire the model-loading failure path in `run_background_recording` through it.
- Identify the stage as Whisper model loading and include the selected model, device, compute type, and download setting in the log context.
- Write the exception type and message plus a full traceback to the existing `voice.log`; show a concise notification naming the failed stage and model, with the exception summary and a pointer to the log.
- Keep the notification one-line and bounded for desktop display. Keep full detail in the log, and do not include transcript or audio contents.

### Task 2: Extend stage reporting across the complete background STT workflow
- Set the active failure stage before microphone setup/capture, WAV finalization, transcription, GPU-to-CPU fallback, and transcript insertion, then route those exceptions through the same reporter.
- Distinguish “model failed to load” from “model loaded, but transcription failed” and “transcription succeeded, but text insertion failed.” Preserve the original GPU failure alongside CPU fallback failure details in `voice.log`.
- Keep no-speech outcomes and existing routine-toast suppression separate from errors; preserve cancellation handling and recorder/WAV cleanup.

### Task 3: Inspect the failure paths and reporting coverage
- Review `run_background_recording`, `load_model`, and `transcribe` to confirm each failing operation is labeled before it runs, reaches one stage-aware notification, and records its exception and traceback in `voice.log`.
- Confirm notifications identify whether failure occurred in recording, model loading, transcription, or insertion, and that empty transcription remains reported as “No speech detected.” Use source inspection only; do not add or run tests.
